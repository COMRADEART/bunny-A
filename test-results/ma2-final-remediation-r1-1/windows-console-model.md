# Windows console-support model

Before correcting the controller, `conhost-lineage.json` reconstructed each of the four refused lifetimes. Fresh CIM birth/image/parent data, held process handles, owner SID and session agree. The held parent's `NtQueryInformationProcess(ProcessConsoleHostProcess, 49)` returns the exact child PID for every role. Each child is the Microsoft-signed System32 image, born 9–20 ms after its parent. The observed kernel association is additional evidence, rather than a filename/parent-PID inference.

The canonical installed launcher uses hidden `Start-Process` for console Node programs. Host and gateway start inside the GUI bootstrap's embedded Windows PowerShell; the tunnel worker starts through the same release launcher. The worker spawns the console cloudflared image. On this Windows installation all four console clients receive distinct console hosts. The GUI bootstrap itself has no console-support descendant. Four live disposable processes using the same hidden launch shape reproduce the console hosts; a GUI-subsystem fixture completes the five-role shape.

Windows documents new-console creation, inheritance and the distinction between a hidden console and `CREATE_NO_WINDOW`. [Microsoft console creation](https://learn.microsoft.com/en-us/windows/console/creation-of-a-console), [creation flags](https://learn.microsoft.com/en-us/windows/win32/procthread/process-creation-flags). The native query class is identified by the maintainer's [phnt process definitions](https://github.com/winsiderss/phnt/blob/master/ntpsapi.h). This internal query is an observed Windows diagnostic interface, not a promised portable Win32 contract. Failed/changed query behavior fails closed; no pathname fallback exists.

The external corrected controller requires: fresh enumeration twice; held current parent and child lifetimes/images; canonical proven parent role; current parent PID; child birth after parent within five seconds of this launch shape; exact Windows System32 image; valid exact Microsoft Windows signer; same SID/session; and the held parent's current kernel console association equal to this child PID. Changed birth, foreign user/session, unrelated parent, absent inspection or parent exit refuses classification. Deeper descendants and fresh topology changes are also refused.

Support classification has no direct termination method. Only the already-authorized five canonical role handles may be stopped, with fresh inspection immediately before each Stop. All support handles are observational and must exit naturally before selection. A remaining support lifetime aborts selection rather than expanding cleanup. The actual disposable parent-exit race refuses historical reconstruction, and an actual foreign Node descendant remains alive after refusal. Adversarial name/path/signer/PID-reuse variations are faithfully simulated through the identical rule; actual dangerous PID reuse is not attempted.

The model lives solely in `test-results/ma2-final-remediation-r1-1/console-ownership.ps1` and the external promotion controller. Candidate runtime, installer, launcher, manifest and ZIP bytes remain unchanged. A release-pin regression test now recognizes the existing exact `MA2-R1` suffix; it is not packaged and does not affect the candidate's tooling pin.
