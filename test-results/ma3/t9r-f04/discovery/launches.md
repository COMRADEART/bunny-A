**Key answers**
- **Ollama:** no path launches `ollama serve`, a worker, or any `ollama` argv. `ollama.exe` is only located (`src/lib/bunny-host/discovery.server.ts:137-139`) and stored as a path string (`adapters.server.ts:142`). All Ollama traffic is HTTP to `127.0.0.1:11434`. If the service is down, Bunny refuses (`src/lib/orch/exec.server.ts:49`) and does not start it.
- **WSL:** no `wsl`, `wsl.exe`, `bash -c` or `sh -c` launch anywhere in `src/` or `scripts/`. `bash`/`sh` appear only in regexes that parse other agents' command text (`src/lib/bunny-host/events.ts:74-80`).
- **cmd.exe:** never launched. `.cmd` npm shims are read, not run (`discovery.server.ts:64-85`), and their targets run as `node <js>` or a native exe. Terminal refuses `.cmd/.bat/.ps1` (`src/lib/bunny-missions/capabilities/process.server.ts:24-29`).
- **Codex/Claude fallback:** none. There is no shell retry and no alternate launcher. `launch()` throws if the executable is missing or changed (`adapters.server.ts:304, 312, 324`). The only fallback is manager-level reroute to a different provider (`src/lib/bunny-host/manager.server.ts:1350`), which can land on Ollama HTTP.
- **Containment:** only Mission `terminal.exec`, git and gh use the native Windows job. Provider sessions (`spawnSession`) use plain spawn plus `taskkill /T /F`.

**Notes for T9R-F04 (integration seams)**
1. **stdin mismatch:** the native launcher hard-codes `hStdInput = NUL` (native/bunny-owned-process.c:88, 98). But `spawnSession` writes the prompt to stdin (adapters.server.ts:236), `codexLaunchArgs` ends with `-` (:400), and `probeCodexCatalog` speaks JSON-RPC over stdin (codex-probe.server.ts:35, 39). Provider sessions and the app-server probe need a stdin pipe, or a prompt passed another way.
2. **No streaming:** `runWindowsOwnedProcess` buffers output into a 200 KB cap and returns only at exit (owned-process-group.server.ts:136-160). `spawnSession` needs line-by-line JSON events, stderr, and a `spawn` event with a PID (adapters.server.ts:214-216). Only `launcherPid` is available, from `inspect()` (owned-process-group.server.ts:113-122).
3. **Stop path:** `spawnSession` terminates with taskkill (adapters.server.ts:198). A job-backed session must call `group.close()` instead, and reconcile with manager survivor sampling.
4. **Single-root group:** `OwnedProcessGroup.spawn` allows one root per group (owned-process-group.server.ts:108). Each provider attempt needs its own group.
5. **Untracked trees:** the `child.kill()` calls in codex-probe.server.ts:31, 36, 50 only kill the root on Windows. Playwright (P26) and `Start-Process` (P25) children are not tracked by any Bunny kill path.
6. **Latent unjobbed branch:** the plain-spawn branch at process.server.ts:65-93 is reachable only when `owned` is false and the command is not git. I found no production caller that reaches it; terminal, connectors and git all set owned or resolve to git.
7. **Stdin left open:** verification and process-tree execFile calls leave stdin as an open pipe (owned-processes.server.ts:20-33). Low risk, since the children do not read stdin.
8. **Not verified:** the 15s survivor-sampling interval, the Calculator relaunch paths beyond the cited lines, and `entry.server.ts`. The scripts grep dropped lines containing the word "test", so a few harness lines may be missing.
