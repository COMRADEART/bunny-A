**2. Google: Gemini CLI and Antigravity CLI** (geminicli.com auth and quota pages, the gemini-cli README, antigravity.google/docs/cli/install, ai.google.dev/api/models)

- **Gemini CLI is gone for consumer accounts.** The official banner says: "Gemini CLI was replaced by Antigravity CLI on June 18th, 2026" for "Unpaid tier and Google One users".
  - 3P: Enterprise Code Assist and paid API-key or Vertex users keep it. The replacement `agy` is reported as closed source.
- **Gemini CLI**
  - License: "Apache License 2.0".
  - Auth modes: Sign in with Google; `GEMINI_API_KEY`; Vertex (ADC, `GOOGLE_APPLICATION_CREDENTIALS` or `GOOGLE_API_KEY`, plus `GOOGLE_CLOUD_PROJECT`).
  - Same ambient-key risk as `ANTHROPIC_API_KEY`: "If you have previously set `GOOGLE_API_KEY` or `GEMINI_API_KEY`, you must unset them to use ADC."
  - Headless: `gemini -p ... --output-format json`.
  - Quotas: Google account "1000 maximum model requests / user / day"; unpaid API key "250 ... / day", Flash only; AI Pro 1,500 per day; AI Ultra 2,000 per day. "when using an API key, you pay per token/call".
  - Status: "`/stats model`", interactive only.
- **Antigravity CLI (`agy`)**
  - Windows install: `irm https://antigravity.google/cli/install.ps1 | iex`.
  - Sign-in: Google account, "Business account", or Enterprise SSO/WIF/ADC. Credentials go in the OS keyring (Windows Credential Manager).
  - Headless use needs `"modelProvider": "gemini"` in `~/.gemini/antigravity-cli/settings.json` plus `GEMINI_API_KEY`. "setting `GEMINI_API_KEY` alone has no effect"; "the CLI never establishes an account session".
  - Usage: `/usage`, interactive only. No status or whoami command.
- **Key validation:** `GET https://generativelanguage.googleapis.com/v1beta/models` (models.list). The page says nothing about billing.
- **What Bunny may implement**
  - `api_key` and `vertex` modes.
  - `native_subscription_cli` only for accounts that still qualify (paid or enterprise). Whether Pro and Ultra still work after 2026-06-18 is UNVERIFIED.
  - Subscription use of `agy` is undocumented, so view-only.
  - A free or Google One login should be reported as "deprecated for account type", not "auth failed".
  - Remove `GEMINI_API_KEY`, `GOOGLE_API_KEY` and `GOOGLE_APPLICATION_CREDENTIALS` from subscription spawns.

**3. GitHub Copilot CLI** (docs.github.com install-copilot-cli, about-copilot-cli and the legacy copilot-requests page; github.blog changelog 2026-04-27)

- **Install and auth**
  - `npm install -g @github/copilot` or `winget install GitHub.Copilot`. Needs "An active GitHub Copilot subscription".
  - Auth: `/login`, or a fine-grained PAT with "Copilot Requests".
  - Env vars: "`COPILOT_GITHUB_TOKEN`, `GH_TOKEN`, or `GITHUB_TOKEN` ... (in order of precedence)". A `GH_TOKEN` or `GITHUB_TOKEN` already set for git would be picked up silently, so Bunny must remove them.
- **Programmatic use:** "include the `-p` or `--prompt`". `--allow-all-tools` lets Copilot run any tool without approval, so Bunny should not pass it by default.
- **Models and usage:** `--model` or `/model`; `COPILOT_MODEL` for custom providers. `/context` shows tokens. No usage or status command.
- **Old `gh copilot`:** the extension was retired on 2025-10-25. Since 2026-01 it just launches Copilot CLI (search-result summary only).
- **Billing:** since 2026-06-01, "all GitHub Copilot plans will transition to usage-based billing"; premium requests are "replaced by GitHub AI Credits".
  - "Credits will be consumed based on token usage". Monthly credits: Pro $10, Pro+ $39, Business $19, Enterprise $39.
  - Legacy annual Pro and Pro+ plans keep "one premium request" per prompt.
  - So every `copilot -p` run is metered. Consent must say so.
- **No documented seat-validation endpoint.** Do not use the undocumented `copilot_internal` endpoints. Terms for automation: UNVERIFIED.

**4. OpenRouter** (openrouter.ai/docs: limits, authentication, get-credits, BYOK, OAuth)

- **Auth:** `Authorization: Bearer <OPENROUTER_API_KEY>`, base URL `https://openrouter.ai/api/v1`.
- **OAuth sign-in (PKCE)**
  - Send the user to `https://openrouter.ai/auth?callback_url=...` with a `code_challenge`, then `POST /api/v1/auth/keys` with the `code_verifier`.
  - "Localhost callbacks are supported on any port". The result is a "user-controlled API key", which suits a Host-owned connect flow.
- **Key and credit check: `GET https://openrouter.ai/api/v1/key`**
  - Returns `limit`, `limit_remaining`, `limit_reset`, `usage` (plus daily, weekly and monthly), `byok_usage*`, `is_free_tier`, `free_model_daily_requests{used,limit,remaining}`, `budgets` and `effective_budget`.
  - The page doesn't say whether the call costs credits; it does no inference. `/api/v1/auth/key` is not on the current page.
  - `GET /api/v1/credits` needs a management key.
- **Free models (`:free`):** 20 requests per minute; 50 per day, or 1,000 per day once 10 or more credits have ever been bought.
- **BYOK (your own provider keys stored in OpenRouter)**
  - Costs "5% of what the same model/provider would cost normally on OpenRouter", with a $25,000/month free allowance.
  - If your keys fail or hit limits, it falls back to shared capacity by default: "Shared capacity spends OpenRouter credits." That is a silent switch to paid, controlled by a per-key setting.
- **What Bunny may implement:** an `api_key` connection, created through PKCE where possible. Its usage numbers are real data from `/api/v1/key`.

**5. Ollama** (docs.ollama.com cloud, FAQ and api/tags; ollama.com/pricing)

- **Local mode needs no account.** "Ollama binds 127.0.0.1 port 11434 by default"; "We don't see your prompts or data when you run locally."
- **Cloud mode**
  - Cloud models "do not need to be downloaded" (example tag `gemma4:cloud`).
  - Through the daemon, sign in via the app Settings or the CLI command `ollama signin`. `ollama signout` is 3P only; there is no whoami.
  - Or use `OLLAMA_API_KEY` with Bearer to `https://ollama.com/api/chat`, with the model list at `https://ollama.com/api/tags`. Whether that list endpoint checks the key is UNVERIFIED.
- **Local-only switch:** `OLLAMA_NO_CLOUD=1` or `disable_ollama_cloud: true` in `~/.ollama/server.json`. After a restart the log shows "Ollama cloud disabled: true".
- **Detecting cloud models:** `GET /api/tags` gives each model optional fields `remote_model` ("Name of the upstream model, if the model is remote") and `remote_host` ("URL of the upstream Ollama host, if the model is remote"). These are the only remote markers; there is no boolean.
  - Bunny should treat a model as cloud if either field is set or the tag ends in `:cloud`/`-cloud` (`-cloud` is UNVERIFIED). Ollama models must not be labelled local by default.
- **Billing:** Free $0; Pro $20/mo with "$60 of usage credits per month"; Max $100/mo with $300. "Usage is measured in tokens at each model's rates". "the session and weekly limits of the old plans no longer apply."
- **Data:** "Prompt or response data is never logged or trained on." Hosting partners must have zero data retention.
- **What Bunny may implement:** `local_runtime` (probe `/api/tags`), and a separate `ollama_cloud` connection that needs explicit consent because it is off-device and metered.

**6. OpenCode** (opencode.ai/docs providers and cli; github.com/anomalyco/opencode)

- **Basics:** MIT license. Windows install: `scoop install opencode` or `choco install opencode`.
- **Credentials:** keys added with `/connect` "are stored in `~/.local/share/opencode/auth.json`". Bunny must never read this file.
- **Commands**
  - `opencode auth login|list|logout`.
  - `opencode run --format json -m provider/model` for headless runs.
  - `opencode models`.
  - `opencode serve --port`, with `OPENCODE_SERVER_PASSWORD` for basic auth. It must not listen on the LAN.
  - `opencode stats` gives "token usage and cost statistics" from local sessions only, so it is an estimate.
- **Logins it supports:** GitHub Copilot device login, "ChatGPT Plus/Pro", OpenCode Zen (curated models) and OpenCode Go ("a low cost subscription plan"). Local providers: Ollama, LM Studio, llama.cpp.
- **Claude subscriptions are off-limits.** Verbatim: "There are plugins that allow you to use your Claude Pro/Max models with OpenCode. Anthropic explicitly prohibits this." The bundled plugins were removed "as of 1.3.0".
- **What Bunny may implement**
  - A CLI adapter whose consent is keyed by the pair (opencode, inner provider), because the inner provider decides who bills.
  - Block Claude subscription credentials going through OpenCode.

**Implications for T13.2**

1. **Ambient credentials.** Subscription spawns should remove the variables below unless the connection is explicitly API mode. Host-only status should record "ambient key present, suppressed", and the value must never reach Agents or the phone.
   - `ANTHROPIC_API_KEY`
   - `XAI_API_KEY`
   - `GEMINI_API_KEY`, `GOOGLE_API_KEY`, `GOOGLE_APPLICATION_CREDENTIALS`, `GOOGLE_GENAI_USE_VERTEXAI`

   - `OPENROUTER_API_KEY`
   - `OLLAMA_API_KEY`
   - `OPENAI_API_KEY`
2. **Billing class.** Give each connection one of: `included_subscription`, `metered_subscription_credits` (Copilot credits, Ollama Cloud, Grok overage), `paid_api`, `free_tier_api`, `local_free`, `unknown`.
   - Check consent at final dispatch and on retries, keyed by provider, account, billing class and project.
   - Moving to another class needs new consent. Examples: Ollama local to `:cloud`, OpenRouter BYOK to shared capacity, Grok login to `XAI_API_KEY`, and a Claude task moving to Codex.
3. **Usage numbers.** Only OpenRouter `/api/v1/key` returns real usage numbers; xAI `/v1/api-key` gives key status but not spend. Everything else stays UNKNOWN, never a number.
4. **Phone view.** Safe to show: `redacted_api_key` and `limit_remaining`. Never show tokens, key ids or `auth.json` contents.
5. **Gemini consumer gap.** For free or Google One accounts, report the Gemini CLI login as deprecated for that account type, and offer a Gemini API key or a view-only `agy` connection instead.
