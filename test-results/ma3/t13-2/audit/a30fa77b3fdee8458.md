## (a) Running your own `claude -p` from a local orchestrator
**Documented and permitted, with conditions.** This is my reading of the documents, not legal advice.
- S1 (excerpt) says subscription usage is meant for native apps: "the Claude web, desktop, and mobile applications and Claude Code".
- S7: "OAuth authentication … is designed to support ordinary use of Claude Code and other native Anthropic applications."
- S6: `-p` is "available as a CLI for scripts and CI/CD".
- S4: `claude setup-token` makes a one-year subscription token "For CI pipelines, scripts, or other environments where interactive browser login isn't available".
- S7: the restrictions do not "prevent an end user from signing in to the unmodified Claude Code binary with their own Claude subscription, including where a platform hosts Claude Code".
- S13 bans access "through automated or non-human means, whether through a bot, script, or otherwise", "Except when you are accessing our Services via an Anthropic API Key or where we otherwise explicitly permit it". The documented `-p` path is the strongest explicit permission available.

Conditions:
1. Run the binary unmodified (S7).
2. Use only your own account, for yourself. S13 says you may not "make your Account available to anyone else". The owner's phone viewing their own Host is fine.
3. Sign-in happens only in Anthropic's flow: the user runs `claude` or `claude auth login` themselves.
4. Usage must stay "ordinary, individual usage of Claude Code and the Agent SDK" (S7). No number is given.
5. If Bunny is ever shipped to other people, S8/S9 apply: "Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK."

## (b) What is explicitly prohibited
- S7: "Anthropic does not permit third-party developers to offer Claude.ai login into their own applications, or to route requests through Free, Pro, or Max plan credentials on behalf of their users. Moreover, developers may not collect, store, or intermediate Claude.ai credentials or session tokens — sign-in to a Claude account must complete through Anthropic's own flow."
- S7: "The Claude Code binary must not be modified" and customers may not "remove, disable, or restrict any authentication method". They also "may not pay for, resell, or intermediate Claude usage on their end users' behalf".
- S14 (excerpt): "Resell, proxy, or otherwise provide access to Claude through unauthorized means", "including services that route requests through consumer subscriptions or misrepresent the product or client being used".
- S1 (excerpt): tools that "misrepresent their identity to Anthropic's servers" or "route third-party traffic against subscription limits" are prohibited "and such use may be enforced against".
- S7: Anthropic "may do so without prior notice".
- S13: no sharing of "Account login information, Anthropic API key, or Account credentials".

## (c) Reading auth state without touching `.credentials.json`
- **`claude auth status`** (S5): "Show authentication status as JSON … Exits with code 0 if logged in, 1 if not … `authMethod` field is one of `none`, `claude.ai`, `oauth_token`, `api_key`, `api_key_helper`, or `third_party`."
  - Locally it returned `loggedIn:true`, `authMethod:"claude.ai"`, `apiProvider:"firstParty"`, `subscriptionType:"pro"`, `configDirectory`, plus identity fields.
  - `subscriptionType` is not in the documented field list, and community bug reports say it can be null or wrong for Max subscribers. Treat it as advisory.
- **Per run** (S11): the stream-json `system/init` event has an `apiKeySource` field. It is one of `"ANTHROPIC_API_KEY"`, `"apiKeyHelper"` or `"/login managed key"`, or `"none"`, which means "No API key. The session authenticates another way, such as a claude.ai login".
- **Plan exhaustion** (S11): `rate_limit_event.rate_limit_info` carries status, `resetsAt`, `utilization` and `errorCode:"credits_required"`. That code means the subscription's included usage is exhausted.
- `/status` is not usable in `-p` mode (S6).
- S4: credentials live in `%USERPROFILE%\.claude\.credentials.json`, and "Claude Code manages `.credentials.json` through `/login` and `/logout`". Bunny must never read this file.

## (d) Ambient `ANTHROPIC_API_KEY` and how to guard against it
- S4 precedence order: cloud `CLAUDE_CODE_USE_*` > `ANTHROPIC_AUTH_TOKEN` > `ANTHROPIC_API_KEY` > `apiKeyHelper` > `CLAUDE_CODE_OAUTH_TOKEN` > profile/federation > subscription `/login`.
- S4/S10: "In non-interactive mode (`-p`), the key is always used when present." With `-p` there is no prompt.
- S10: the key "is used instead of your Claude Pro, Max, Team, or Enterprise subscription even if you are logged in".
- S3 (excerpt): "you'll be charged via API pay-as-you-go rates using the API account associated with that key".
- S6: in bare mode Claude Code "never reads OAuth credentials", so `--bare` forces API billing.

**Bunny is exposed today:**
- `src/lib/bunny-host/adapters.server.ts:227` and `:351` both build `const env = { ...process.env }; delete env.CLAUDECODE;`, so every Anthropic auth variable on the Host passes straight into `claude -p`.
- `ClaudeAdapter.detect()` (`adapters.server.ts:511-537`) reads `authMethod` but only displays it (`:535`). Any `loggedIn:true` counts as authenticated, including `api_key`.
- `ClaudeNormalizer.normalize` (`src/lib/bunny-host/events.ts:193-228`) ignores `apiKeySource`.
- `claudeLaunchArgs` (`adapters.server.ts:572-578`) uses `--safe-mode`. Per S5, authentication "work[s] normally" under safe mode, so an `apiKeyHelper` in user settings still applies on write runs.
- An allowlist pattern already exists to reuse: `workerEnvironment()` / `WORKER_ENV_ALLOWLIST` in `voice/voice-worker.server.ts:236-249`.
- The machine is safe right now: all of these variables are unset in the session and in the User and Machine environment.

**Guard (fail closed, at final dispatch and on every retry):**
1. **Allowlist or scrub the child's env** per connection mode. Remove `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_BASE_URL`, the `CLAUDE_CODE_USE_BEDROCK|VERTEX|FOUNDRY|ANTHROPIC_AWS` vars, `ANTHROPIC_PROFILE`, `ANTHROPIC_FEDERATION_RULE_ID`, `ANTHROPIC_ORGANIZATION_ID`, `CLAUDE_CODE_OAUTH_TOKEN`, and `CLAUDE_CONFIG_DIR` unless the registry pins it. Match names case-insensitively on Windows.
2. **Preflight `claude auth status` in that same env.** Require `authMethod==="claude.ai"` and `apiProvider==="firstParty"`. Otherwise refuse with "would bill API". Never downgrade silently.
3. **Runtime tripwire.** If `system/init` shows `apiKeySource!=="none"` in subscription mode, kill the process group and mark the run as a billing-mode mismatch.
4. **Never pass `--bare`** for subscription runs.
5. **Make API-key mode a separate, consented connection.** Inject the key from Bunny's DPAPI vault into that one child only, label it "billed at API rates to key owner", and optionally pass `--max-budget-usd`. That cap is a client-side estimate (S5).
6. **Never auto-switch on `credits_required`.** For subscription runs, show `total_cost_usd` as an estimate only: S12 says the session cost figure "isn't relevant for billing purposes" for subscribers.

## Consent note (T13.1 limitation 7)
- Moving a Task from Claude to Codex changes account and billing. Consent should be recorded per provider, account fingerprint, connection mode and project, and re-checked at final dispatch, on retries and on fallbacks.
- The account fingerprint can be a never-displayed hash of the `claude auth status` orgId or email.
- Changing `CLAUDE_CONFIG_DIR` changes the account (S4).
- Claude's own `--fallback-model` stays within the same account.
