**Biggest risks for T13.2**

1. **Device snapshot is allow-by-default per field.** `deviceSnapshot()` (device-authority.server.ts:369-416) and `dashboardSnapshot()` (presentation.ts:486) both spread `...snapshot`. Only the fields they override are redacted; `intelligence` is removed explicitly at :414. Any new `HostSnapshot.connections` field reaches the phone unredacted unless `deviceSnapshot` overrides it.
2. **Device command responses carry raw `extra` data.** For devices, http.server.ts:1026-1039 re-projects only `extra.agents`, `extra.agent` and `extra.mission`. Any `extra.data` is sent to the phone as-is.
3. **The gateway drops unlisted command data.** `dashboardCommand` (presentation.ts:642) forwards `data` only for voice actions and an explicit list of `project.*` actions plus `operation.status`. A `connections.*` command returning `extra.data` loses it unless added there. Returning state through the snapshot (the `intelligence.*` pattern) avoids this.
4. **Ambient API keys reach provider CLIs.** adapters.server.ts:227 and :351 build `env = {...process.env}` and delete only `CLAUDECODE`. An ambient `ANTHROPIC_API_KEY` or `OPENAI_API_KEY` therefore reaches the CLI and can switch subscription work to paid API billing. Those two lines are where per-mode stripping or injection belongs. `owned-process-group.server.ts:238` also defaults to `process.env`.
5. **There are two launch points; both need the consent gate.** First launch is `adapter.launch` at manager.server.ts:1745. Retry/reroute is `targetAdapter.launch` at :1723; `rerouting` is computed at :1666, and Mission tasks are checked there by `missionScopeCheck`/`missionAttemptAdmission` (:1668-1685). Launch revalidation also reroutes through `rerouteFromDecision` (:1449-1470), and advice is applied in submit by `applyDecisionAdvice` (:1088). A Connection consent check at all of these, for direct and Mission tasks alike, closes T13.1 limitation 7 (Claude moved to Codex).
6. **New tables must be created at boot, before the state marker refresh.** An installed boot refuses unless `user_version == 3` and the sha256 of `sqlite_master` matches `state-layout.json` (state-paths.server.ts:47-53). `refreshStateMarker()` re-fingerprints once at http.server.ts:355. A table created lazily after that line makes the next installed boot fail with "unexpected schema".

**Authentication and dispatch (http.server.ts)**
- The server listens on loopback only.
- Host header must be `127.0.0.1`/`localhost:<port>`; any `Origin` or cross-site request gets 403 (:579-582).
- Only an exact `Bearer <cred>` header counts (:587). The workstation token is checked with a timing-safe compare (:588).
- Devices are re-authenticated on every request via `authenticateDevice(db, sha256(bearer))` (:590), including a re-check after the body arrives (:657-660). A device bearer is registered as a diagnostic secret and its responses are marked `DEVICE_RESPONSES` (:592).
- **The default-deny gate is `if (device) assertDeviceAction(action)` at :663**, before data parsing or dispatch.
- After that come the epoch/hostId `expect` check (409 `HOST_IDENTITY_CHANGED`/`HOST_EPOCH_CHANGED`) and the per-principal operation ledger (`mutating()`; every owner-only action counts as mutating).
- `safeActions` (:701-720) bypass `containment.assertAccepting` while the Host is degraded.
- Routing by family: `AGENT_ACTIONS`, `VOICE_ACTIONS` (devices refused), `MISSION_ACTIONS`, the `project.` prefix (with `hidePaths` for devices), then the switch.
- Errors (:1040-1079):

  | Error | Status / code |
  |---|---|
  | `HostUnavailableError` | 503 `HOST_UNAVAILABLE` |
  | `WorkstationRequiredError` | 400 `WORKSTATION_REQUIRED` |
  | `CodedRefusal` | its own status and code |
  | `CommandRefusedError` | 400 `REFUSED` |
  | anything else | 400 `FAILED`, generic message, plus a containment incident |

  Only `CommandRefusedError` subclasses expose their message, after `safeError(error,[token])`.
- Older owner-only cases (`policy.*`, `provider.configure_path`, `remote.configure`, `thermal.configure`, `legacy.import`, `verification.record`) use a plain `Error`. New code should use `WorkstationRequiredError` or `CommandRefusedError`.
- `audit.command` records the action name only; device refusals are journaled as `audit.device_refused`.
- `device.revoke` calls `endDeviceGrants()` (:1086-1147), which ends answers, staging, batches, Agentic consents and envelopes the device granted. Any device-attributable connection consent would need ending there too.

**How `intelligence.*` is gated (:768-795)**
- None of these actions is in `DEVICE_RIGHTS`, so a phone is refused at :663. Each case also has its own `if (!local) throw new WorkstationRequiredError(...)`.
- `credential.save` registers the key as a diagnostic secret before validation, local and shape-valid keys only (:773).
- A billable `intelligence.test` requires `confirmBillable === true`.
- `submit` calls `manager.assistDecision` only when `local` (:758-764). Devices never spend the TypeSafe budget, and `decisionAssistance` is never accepted from the HTTP body (`validateSubmit` :82-102).

**Secrets (jev-secrets.server.ts)**
- `DpapiProtector` runs `execFile(systemTool("powershell.exe"), ["-NoProfile","-NonInteractive","-ExecutionPolicy","Bypass","-Command",DPAPI_SCRIPT])` with a 20 s timeout and 64 KB buffer.
- The plaintext travels base64 on **stdin**; only the mode goes in env (`BUNNY_DPAPI_MODE`). Scope is CurrentUser.
- **Entropy is hard-coded as `'Bunny-A/TypeSafe-Jev/credential/v1'` (:24).** It fails closed on non-Windows and returns a generic error.
- `TestProtector` is a reversible test-only fake, injected via `startHost({intelligence:{jevProtector}})`.
- `API_KEY_SHAPE = /^[\x21-\x7e]{8,512}$/`.
- `JevSecretStore` uses the singleton table `jev_credentials(id CHECK(id=1), ciphertext BLOB, protector TEXT, updated_at)`.
  - `save()`: shape check, `registerDiagnosticSecret`, protect, refuse if the ciphertext contains the plaintext, upsert with the protector kind.
  - `retrieve()`: refuses on protector mismatch, says "replace it" on decrypt failure, re-registers the secret on every read.
  - `hasCredential()` and `updatedAt()` expose existence only.
- Outbound TypeSafe calls are pinned to an approved https origin, refuse redirects, and refuse to send when `NODE_TLS_REJECT_UNAUTHORIZED=0` (typesafe-jev.server.ts:76-138).

**Redaction (failure.server.ts)**
- `registerDiagnosticSecret` (:56) keeps a bounded process-wide set (512 entries, 4-8192 chars).
- `safeError` (:70-144) hides registered secrets and any env value whose name matches `/token|secret|password|passwd|api.?key|cookie|authorization|credential/i`, which covers `ANTHROPIC_API_KEY`. It also scrubs Bearer tokens, auth/cookie headers, key=value secrets, `sk-`/`ghp_`/`github_pat_` tokens and URL userinfo, and bounds lengths.

**Persistence**
- `HostDatabase` (persistence.server.ts:16-117) creates the core tables and sets `PRAGMA user_version=3`. Column migrations use `PRAGMA table_info` then `ADD COLUMN` (:31-36). The journal keeps the newest 20,000 events.
- Every other table is created by its owner's constructor with `CREATE TABLE IF NOT EXISTS`, never touching `user_version` (rule stated in routing-store.server.ts:1-9).
- `settings(key, value)` keys use versioned names and JSON with a safe fallback (`jev_policy_v1`, `jev_guard_v1`, `laya_enabled_v1`, `provider_paths`, and others). Settings rows never hold secrets, and data rows don't affect the schema hash.

**`jev_usage` retention gap**
- Table and index: typesafe-jev.server.ts:236-237. Nothing ever prunes it.
- Rows are reserved as pending before sending (:375), settled or deleted if never sent (:381-398), and turned to `unknown_restart` at boot (:239).
- `usage()` (:326-343) counts the current session (no time bound), billable rows since local midnight, and the last billable row.
- A retention policy must keep the current session's rows, all rows from today, and the newest billable row. A safe shape is `DELETE … WHERE at < min(now−N days, dayStart) AND session_id <> current`, run in the JevService constructor and periodically. It needs no DDL, so the schema hash is unchanged.

**Recipes**
- **New owner-only family (`connections.*`)**
  1. Do not add it to `DEVICE_RIGHTS`.
  2. Add a family branch near :722-747, or switch cases, each with `if (!local) throw new WorkstationRequiredError("…on the workstation (Windows Host).")`.
  3. Throw `CommandRefusedError` for validation failures.
  4. Call `registerDiagnosticSecret` on secret fields before validation.
  5. Put revoke/disconnect in `safeActions`.
  6. Journal secret-free details and add `LABELS` entries.
  7. Prefer snapshot state, or extend the `dashboardCommand` allowlist.
  8. Add store helpers next to use-island.ts:1120.
- **Phone-visible field**
  1. Add an optional field to `HostSnapshot`.
  2. Populate it in `manager.snapshot()`.
  3. Override it explicitly in `deviceSnapshot` with a redacted builder: provider, mode label, state enum, coarse usage. No handles, accounts, paths or error text.
  4. Never put handles on agent or task fields. Adapters already receive a frozen `structuredClone`.
- **New DPAPI secret kind**
  1. Make entropy a per-kind label passed through env (it isn't secret), keeping the Jev string byte-for-byte so existing ciphertext still decrypts.
  2. Generalize to a keyed store that keeps every `JevSecretStore` invariant.
  3. Inject `TestProtector` through a manager options seam.
- **New table**: an additive constructor in a class built inside the `TaskManager` constructor (next to manager.server.ts:174-176) or otherwise before http.server.ts:355. Store `granted_by` as an actor string so `endDeviceGrants` can find device-granted rows.
