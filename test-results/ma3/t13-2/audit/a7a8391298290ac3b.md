## 1. Cursor CLI
- The old URL docs.cursor.com/en/cli/reference/authentication now redirects (308) to cursor.com/docs. I fetched the page at cursor.com/docs/cli/reference/authentication.
- **Binary name:** current docs use `agent`; older docs use `cursor-agent`. Bunny should check for both names. `agent` is a generic name on PATH, so confirm it is Cursor with `agent about --format json`.
- **Auth commands (FETCHED):**
  - `agent login` "opens your browser to sign in with your Cursor account, and credentials are stored locally."
  - `agent status` (alias `whoami`) "View authentication status". It shows "account info and endpoint configuration".
  - `agent logout` "clears stored credentials."
  - `NO_OPEN_BROWSER=1` prints the login URL instead of opening a browser.
  - For automation, a user API key goes in the `CURSOR_API_KEY` env var ("recommended") or `--api-key`.
  - Where credentials are stored is not documented (UNVERIFIED).
- **Parameters (FETCHED, /cli/reference/parameters):**
  - `-p, --print`: "Has access to all tools, including write and shell."
  - `--output-format text|json|stream-json`, which only works with `--print`.
  - `-f/--force` ("Force allow commands unless explicitly denied"), with alias `--yolo`.
  - `--sandbox enabled|disabled`, `--trust` (headless only), `--workspace`, `--model`, `-H` custom headers, `--resume`/`--continue`.
  - `status`/`whoami` and `about` both take `--format text|json`. That gives a machine-readable status probe. Whether the JSON includes the email is UNVERIFIED, so redact it anyway.
  - `models` lists the models available to the account.
- **Headless (FETCHED):** "Combine `--print` with `--force` (or `--yolo`) to modify files in scripts." Without `--force`, changes are only proposed.
- **stream-json output (FETCHED):** the first `system/init` event includes `"apiKeySource": "env|flag|login"`, plus `session_id`, `model`, `permissionMode`, `cwd`. Other events are `assistant`, `tool_call` started/completed (`call_id`), and `result` (`duration_ms`). There is no dollar or usage field in the doc.
  - This matters for T13.2: in subscription-login mode, Bunny should abort if `apiKeySource != "login"`. That catches an ambient `CURSOR_API_KEY` that leaked into the child.
- **Platform (FETCHED):** both "Windows (native)" and WSL are supported. Native install is `irm 'https://cursor.com/install?win32=true' | iex`. It auto-updates; `agent update` updates manually.
- **Billing and terms:**
  - Forum post by "deanrie", 2026-07-10; the page doesn't confirm a staff role: "Billing is usage based under the plan and limits of the account tied to the API key."
  - Same post: headless print mode is "exactly what it's built for, scripts, CI, automation", and "you can't give third parties access to Cursor or usage under your account".
  - Terms of service (updated Sept 3, 2026): s.1.5(iii) bars "rent, lease, lend, or sell the Service"; s.1.5(xi) bars knowingly letting a third party do so.
  - So `CURSOR_API_KEY` bills the same Cursor account and plan as browser login. The distinction is which Cursor account, not subscription versus paid API.
  - Using your own OpenAI/Anthropic keys in the CLI is reportedly not supported (search result only, UNVERIFIED).
- **Bunny modes:**
  - native-subscription-cli: the user runs `agent login`; Bunny spawns `agent -p --output-format stream-json` with `CURSOR_API_KEY` removed from the env and verifies `apiKeySource=login`.
  - api-key: a Host-held key injected into the child as an env var, never as a command-line argument.
  - view-only: `status --format json`.
  - `--force` is off by default. Phone and Agents can never trigger login.

## 4. Anthropic policy (FETCHED, code.claude.com/docs/en/legal-and-compliance)
- Subscription OAuth is "intended exclusively for purchasers of Claude Free, Pro, Max, Team, and Enterprise subscription plans and is designed to support ordinary use of Claude Code and other native Anthropic applications."
- "Anthropic does not permit third-party developers to offer Claude.ai login into their own applications, or to route requests through Free, Pro, or Max plan credentials on behalf of their users. Moreover, developers may not collect, store, or intermediate Claude.ai credentials or session tokens — sign-in to a Claude account must complete through Anthropic's own flow."
- What is allowed: an end user "signing in to the unmodified Claude Code binary with their own Claude subscription". Also: "Customers may not pay for, resell, or intermediate Claude usage on their end users' behalf."
- News reports (search results): server-side blocks on 2026-01-09 and a docs clarification on 2026-02-19.
- For Bunny: Claude subscription work goes only through the user's own logged-in, unmodified `claude` binary. Bunny never reads or copies Claude credentials, and strips `ANTHROPIC_API_KEY` from the child env in subscription mode.

## 6. Recommendations for T13.2 across all adapters
1. **Child env:** start each adapter's child process from an allowlisted env. Strip `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `CURSOR_API_KEY`, Cline and OpenCode keys and `OLLAMA_API_KEY`, unless that key is the selected connection mode.
2. **Check after spawn:** confirm the credential source the tool reports. For Cursor that is `system/init.apiKeySource`; Claude Code has a similar field in its own stream.
3. **Redacted status:** status probes return only installed/version, authenticated (true/false), provider ids, credential type and plan label. Emails are redacted for the phone, and tokens never leave the Host.
4. **Override unsafe defaults:** Cline auto-approve on, Cursor `--force`, an unauthenticated `opencode serve` with `PUT /auth`, OpenCode Go "Use balance" overflow, and Ollama `:cloud` models.
5. **Logins:** always user-initiated in the vendor's own flow, never started by Agents or the phone.
6. **Model lists:** read live and never hard-code. ClinePass has already removed models that this machine's profiles still name.
