# T6 execution contract

MissionManager remains the sole step/dependency scheduler. `crossApp` is optional additive metadata on existing MissionStep records: canonical input references only. Existing identity, attempts, scope, verification and artifact fields are retained. Explicit plans remain proposals; operation names resolve only through the Host's positive Capability Bus catalog.

T6 consent is a signed additive exact-operation list inside the existing finite T5 envelope. Browser origins and exact Calculator operation digests derive from the canonical reviewed plan. The plan digest includes dependencies, input references and postconditions. A browser grant does not grant desktop, Git or terminal authority. T5 canonical grants, risk, Agent/Mission/step identity, generation, revisions, expiry and atomic budget admission still apply.

Terminal keeps the accepted immutable pure-read Node-check boundary. Arbitrary npm/project scripts, shells and free-form model commands remain unsupported. Delegated Git adds only fixed read operations, with environment/config/hooks/external diff/text conversion restrictions. Worktree and Git write families keep their separate approval boundary.

Browser execution uses a separate Mission-owned profile/session and exact origin/network restrictions. Private destinations remain blocked; development loopback requires an explicit Host fixture seam plus exact origin consent. A durable session reference stores URL/origin/provenance, never raw cookies or OS handles. Broad browser mutation/download remains unsupported under T6 delegation unless a reviewed bounded adapter can establish its independent authority.

Calculator uses the existing T9R acquisition lock, current package/lifetime checks and exact arithmetic controls. Target identity is execution state, never a grant. GUI uncertainty is UNKNOWN replay safety. Stop/revoke prevent new admission; completed evidence is retained. Production and user-owned resources are never cleanup targets.

Capability results are persisted by reference in the existing Mission ArtifactStore, with bounded safe semantic fields, provenance and SHA-256. Only verified canonical dependency outputs may feed later steps, and only file-content data is eligible initially. Every resolved operation is authorized again. Independent postconditions execute read operations through the same Bus, consume finite allowance, and create verification evidence before completion.

The primary gate is a deterministic preauthored real Windows Mission across files, Git, exact terminal, isolated browser and UIA. It proves orchestration, not unrestricted model planning. Simulated provider I/O is reported separately. The final verdict requires the real integrated workflow and all existing 913 distinct tests retained.
