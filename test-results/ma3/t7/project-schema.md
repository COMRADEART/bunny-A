# Project registry contract

The existing Host SQLite `projects(id,record)` remains canonical. T7 adds indexed lifecycle, favorite, creation/activity timestamps, display name and bounded searchable metadata. `ma3.projects.v1` records retain the historical ID and path reference; add description, directory identity, source/type, owner scope, tags, favorite, revision and lifecycle. No new Project model/provider ownership exists. The legacy `preferred` field is normalized to `auto` and is not routing authority.

Supported states are ACTIVE, INACTIVE, ARCHIVED, MISSING_ROOT and NEEDS_RELINK. Root loss/replacement currently projects NEEDS_RELINK. Registration validates canonical directory identity, refuses links and unsupported Windows paths, and writes metadata only. Same names/remotes do not merge IDs; the same proven directory deduplicates registration. Empty creation explicitly creates one random folder under configured `workspace/projects`. No script, dependency installation, Git initialization or remote fetch runs during registration.

Archive/restore/rename/favorite/tag edits affect metadata, preserve files and canonical history, and require the current revision. Relink requires explicit confirmation, current revision, current accessible identity, no conflicting registered identity and no active Mission. Old Missions retain their original frozen root and require a new reviewed plan after root change. Legacy remove now archives; the former delete branch is removed.

The migration transaction adds columns/indexes, retains IDs and original malformed row bytes, quarantines invalid/ambiguous rows, and never assigns unrelated Missions. Repeat migration is idempotent. Rollback must be separately reviewed: stop only the relevant Host, back up its SQLite database plus WAL consistently, preserve owned manifests/artifacts, and restore the matching pre-T7 database/source pair. There is deliberately no automatic downgrade or destructive down-migration. Production was not migrated.

Project-linked Missions, Tasks, Agents, artifacts and events are bounded indexed projections of their existing owners. Default page 50; maximum 100; UI pages 24/25; offset maximum 100000. Detail sanitizes private prompts/output/diagnostics. Explicit hash-checked artifact opening is separate from public history projection. Current Agent queries are bounded to requested IDs. The global pre-existing Host snapshot is unchanged except bounded Project projection.
