# Project context and admission contract

ProjectContextResolver resolves current Project/Mission/step/Agent workspace against the existing current T5 envelope. Snapshots record Project, Mission, logical step, actual model Task when bound, root identity, bounded repository HEAD reference, explicit file hashes/identities and exact dependency artifact references. Deterministic work uses the canonical step ID as taskId; model Tasks bind their actual TaskManager ID before approval. Consent ID/revision/generation is an observation reference, not a grant.

Limits: 12 explicitly selected files, 64 KB aggregate content observation, 24 dependency artifact references, 16 KB serialized snapshot, 20 retained snapshots per step, bounded root-ancestor lookup and indexed Project identity candidates. No entire repository or raw README is automatically added to model prompts. Existing Mission memory remains the memory authority. Secret-bearing filenames, Host state, browser profiles, links and another Agent's scratch are excluded. No hidden model reasoning or raw selected content is stored in snapshots.

Root/branch/file identity is revalidated; repository branch changes under the same T5 consent require fresh review, and model admission revalidates its actual Task-bound snapshot. Uncertain launch context goes to the existing permission/review path with CONTEXT_CHANGED. Root relink never transfers historical Mission authority. Cross-Project access requires exact current T5 roots, operations and identities. T5 scope/budget/revision/generation checks retain precedence; T7 does not grant, schedule or route execution.

Model Tasks continue through TaskManager and routing-policy-v1. Per-Task objective, scope, privacy and model constraints stay canonical. A controlled actual-router proof selects two different eligible models for the same Project with simulated discovery seams; no provider execution is claimed. The integrated Windows acceptance uses a preauthored deterministic five-step graph, real capabilities and independent verification, with zero model calls.
