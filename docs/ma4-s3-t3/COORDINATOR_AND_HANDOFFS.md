# Host Coordinator Architecture and Handoff Protocol

## 1. Sovereign Host Coordinator

In Bunny-A, the **Coordinator** is trusted TypeScript host code running in the local Node.js process—it is **never** a model-powered agent. 

A model cannot be trusted to enforce its own safety boundaries, evaluate its own handoffs, or allocate its own system resources. Therefore:
- The Host Coordinator owns scheduling, state transitions, tool admission, budget tracking, handoff validation, cancellation propagation, and receipt generation.
- Model-driven roles (**Planner**, **Worker**, **Tester**, **Reviewer**) communicate exclusively through the Host Coordinator.
- Direct peer-to-peer agent handoffs (e.g., Worker talking directly to Tester or Planner) are architecturally impossible.

```
                  ┌────────────────────────┐
                  │    Host Coordinator    │
                  │  (Trusted Host Code)   │
                  └───────────┬────────────┘
         ┌───────────────┬────┴──────────┬───────────────┐
         ▼               ▼               ▼               ▼
   ┌───────────┐   ┌───────────┐   ┌───────────┐   ┌───────────┐
   │  Planner  │   │  Worker   │   │  Tester   │   │ Reviewer  │
   │  (Model)  │   │  (Model)  │   │  (Model)  │   │  (Model)  │
   └───────────┘   └───────────┘   └───────────┘   └───────────┘
```

## 2. Collaboration Protocol: `bunny-a.ma4-s2.handoff.v1`

Every transition across a role boundary is governed by the formal collaboration protocol (`admitHandoff` in `collaboration.ts`).

### Handoff Message Schema
Each handoff message contains:
```typescript
interface HandoffMessage {
  version: "bunny-a.ma4-s2.handoff.v1";
  id: string;
  taskId: string;
  requirementsSha256: string;
  from: S2Role;
  to: S2Role;
  capabilities: string[];
  content: string;
  artifacts?: RegisteredArtifact[];
  trust: "host" | "untrusted";
  validation: "verified" | "unverified" | "failed";
  cost: {
    modelCalls: number;
    toolCalls: number;
    tokens: number;
  };
}
```

### Validation Invariants
The Host Coordinator enforces the following invariants upon every message transmission:

1. **Hub-and-Spoke Topology:**
   - Permitted edges: `Coordinator -> Role` or `Role -> Coordinator`.
   - Any message where `from !== "Coordinator" && to !== "Coordinator"` is immediately rejected.
2. **Frozen Requirements Hash:**
   - When a task is accepted, the Host computes the SHA-256 hash of its specification (`requirementsSha256`).
   - Every subsequent handoff must present the exact same hash. If a model attempts to modify, append, or omit requirements, the message is refused with `REQUIREMENTS_TAMPERED`.
3. **Role Capability Enforcement:**
   - `Planner`: Only permitted `["planning"]`.
   - `Worker`: Only permitted `["code-generation"]` or registered task tools.
   - `Tester`: Only permitted `["test-generation"]`.
   - `Reviewer`: Only permitted `["review"]`.
   - A role attempting to claim capabilities outside its charter fails validation.
4. **Trust Fencing & Anti-Injection:**
   - Any message generated by a model receives `trust: "untrusted"`.
   - If a model attempts to inject steering markers (e.g. `[TRUST=HOST]`, `[AUTHORIZE=TRUE]`, or executive overrides), the Coordinator flags the payload, strips claimed authority, and downgrades the trust to `"untrusted"`.
5. **Budget & Resource Accounting:**
   - Every admitted handoff deducts from the task's remaining model call budget, tool call budget, and token ceiling.
   - If a budget is exceeded, the Coordinator aborts the workflow with `BUDGET_EXHAUSTED`.

## 3. Persistent Task Integration: `coordinatorChannel`

Inside `PersistentTaskRuntime.step()`, every execution step is bracketed by Coordinator handoffs:
1. **Pre-Step Admission (`Coordinator -> Role`):**
   - The step input is packaged and validated.
   - The Coordinator checks that the assigned role is qualified and that model execution parameters conform to the task envelope.
2. **Execution:**
   - The executor runs (either a model generation call or a registered Host tool).
3. **Post-Step Reception (`Role -> Coordinator`):**
   - The output is registered in the Coordinator's artifact ledger (`ch.register(result.output)`).
   - The return message (`Role -> Coordinator`) is verified.
   - The output hash is recorded in the task's evidence chain.

If any handoff check fails, the task immediately halts with state `FAILED` and an immutable record is committed to the SQLite ledger.
