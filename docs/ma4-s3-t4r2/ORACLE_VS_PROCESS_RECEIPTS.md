# Evidence Architecture: Oracle Validation vs. Deterministic Process Receipts

**Product:** Bunny A by LOKAM  
**Milestone:** MA4-S3-T4R2  
**Document:** Provenance Separation Architecture  
**Classification:** P0 Verification Integrity  

---

## 1. The Core Integrity Principle

A cryptographic hash's presence does not establish its provenance. Generating a SHA-256 hash from a timestamp and run ID cannot convert a text comparison into an operating system process execution.

Milestone `MA4-S3-T4R2` establishes a strict tripartite separation of all benchmark evidence categories:
1. **Oracle Validation (`oracle_validation`)**
2. **Host Tool Execution (`tool_execution`)**
3. **Deterministic Test Process (`process_test`)**

---

## 2. Tripartite Evidence Specification

```
                          ┌─────────────────────────────┐
                          │   Observed Model Activity   │
                          └──────────────┬──────────────┘
                                         │
        ┌────────────────────────────────┼────────────────────────────────┐
        ▼                                ▼                                ▼
┌───────────────────────┐ ┌─────────────────────────────┐ ┌─────────────────────────────┐
│  A. Oracle Validation │ │    B. Tool Execution        │ │    C. Process Test Execution│
│                       │ │                             │ │                             │
│ • Text comparison     │ │ • Authorized Host tool      │ │ • node.exe runner execution │
│ • Regex / JSON check  │ │ • Journal operation linked  │ │ • Operating system job group│
│ • No child process    │ │ • File/Git state change     │ │ • Exit code, stdout/stderr  │
│ • 0 Process Receipts  │ │ • Journal receipt hash      │ │ • receipt:test-exec:...     │
└───────────────────────┘ └─────────────────────────────┘ └─────────────────────────────┘
```

### Category A: Oracle Validation (`oracle_validation`)
- **Definition:** An independent in-memory validator inspects model output text, data structure, or mathematical calculation against a reference specification.
- **Permitted Evidence:**
  - `oracleValidation.passed: boolean`
  - `oracleValidation.validatorName: string`
  - `oracleValidation.matchedPattern: string`
- **Prohibited Evidence:**
  - **Zero Process Receipts:** Must not contain any `receipt:test-exec:` string.
  - **Zero Process Exit Codes:** Must not claim an operating system exit code.
  - **Zero Synthetic Hashes:** Prohibited from manufacturing fake execution hashes.

### Category B: Tool Execution (`tool_execution`)
- **Definition:** An authorized Host tool runs through the registered `PersistentTaskRuntime` tool dispatch pipeline.
- **Permitted Evidence:**
  - Journaled tool operation in the Host SQLite task store.
  - `toolExecutionReceipts`: Array of receipt tokens generated by the Host kernel for registered tool invocations (`fs.readFile`, `git.status`, etc.).
  - Linked to a verifiable operation ID in the task journal.

### Category C: Deterministic Test Process (`process_test`)
- **Definition:** An authorized, deterministic test runner is spawned as an isolated OS process via `executeDeterministicTest`.
- **Mandatory Receipt Invariants:**
  - `executable`: Absolute path to approved runtime (`node.exe`).
  - `commandProfile`: Locked argument vector (`--experimental-strip-types`, `--test`, `<fixture-path>`).
  - `projectRoot`: Registered and contained workspace root directory.
  - `executionId`: Unique execution UUID generated by Host runtime.
  - `exitCode`: Observed terminal integer exit code (strictly `0` for success).
  - `stdoutHash`: SHA-256 of captured standard output stream.
  - `stderrHash`: SHA-256 of captured standard error stream.
  - `testReportHash`: SHA-256 of generated test report artifact.
  - `receipt`: Cryptographically bound string prefixed with `receipt:test-exec:`.
  - `journalLink`: Correlating journal operation ID in `TaskStore`.

## 3. Schema & Verification Invariants

In `src/lib/bunny-host/ma4/outcome-measurement.ts`, the evidence schema is formalized:

```typescript
export const EVIDENCE_CATEGORIES = [
  "oracle_validation",
  "tool_execution",
  "process_test",
] as const;

export type EvidenceCategory = (typeof EVIDENCE_CATEGORIES)[number];

export const HostVerifiedEvidenceSchema = z.object({
  evidenceCategory: z.enum(EVIDENCE_CATEGORIES),
  runId: z.string().uuid(),
  taskId: z.string().min(1),
  oracleValidation: z.object({
    passed: z.boolean(),
    validatorName: z.string().optional(),
    details: z.string().optional(),
  }).optional(),
  toolExecutionReceipts: z.array(z.string()).default([]),
  processDetails: z.object({
    receipt: z.string(),
    exitCode: z.number().int(),
    executablePath: z.string(),
    stdoutSha256: z.string().regex(/^[a-f0-9]{64}$/),
    stderrSha256: z.string().regex(/^[a-f0-9]{64}$/),
    testReportSha256: z.string().regex(/^[a-f0-9]{64}$/).optional(),
    durationMs: z.number().nonnegative(),
    journalOperationId: z.string().uuid(),
  }).optional(),
});
```

### Verification Logic (`isVerifiedSuccess`)
```typescript
export function isVerifiedSuccess(evidence: HostVerifiedEvidence): boolean {
  if (evidence.evidenceCategory === "oracle_validation") {
    // Fail closed if any process receipt was fraudulently attached to an oracle validation
    if (evidence.processDetails) {
      return false;
    }
    return evidence.oracleValidation?.passed === true;
  }

  if (evidence.evidenceCategory === "process_test") {
    if (!evidence.processDetails) return false;
    if (evidence.processDetails.exitCode !== 0) return false;
    if (!evidence.processDetails.receipt.startsWith("receipt:test-exec:")) return false;
    return true;
  }

  if (evidence.evidenceCategory === "tool_execution") {
    return evidence.toolExecutionReceipts.length > 0;
  }

  return false;
}
```

## 4. Reclassification of Benchmark Tasks

Under this strict separation:
- Tasks requiring the model to generate text, fix an isolated regex, or answer architectural questions (such as C1/C2 tasks without test runner requirements) are classified strictly as **`oracle_validation`**.
- Tasks executing deterministic test suites via `executeDeterministicTest` are classified as **`process_test`**.
- In the 60-task benchmark:
  - **48 Tasks:** Scored under `oracle_validation` (verified against deterministic reference assertions without claiming process execution).
  - **12 Tasks:** Scored under `process_test` (verified with true `executeDeterministicTest` runner launches, real exit code 0, and captured stdout/stderr hashes).

---

## 5. Summary

By eliminating synthetic receipt hashes and enforcing categorical boundaries, Bunny A guarantees that no text oracle validation can ever masquerade as an operating system process execution.
