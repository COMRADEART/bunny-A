## Visual review boundaries

The 12 contact sheets were reviewed in both variants for desktop, narrow Windows and mobile browser layouts; full-size Settings, Server Control, Studio, Lotus and accessibility screenshots were additionally inspected. No claim is made that every populated row, tooltip, modal, pressed/hover state or spoken accessibility announcement passed. Graphite rim highlights and Silver elevation exist already, but their optical-depth quality relative to the supplied concepts still requires E5B/E5C owner review. Existing canonical characters must not be replaced to match a concept picture.

The two preliminary capture issues (early hydration readiness and embedded Lotus response timing) were corrected in the runner, and the final evidence was recaptured. They are harness issues, not product defects. A generic Vercel preview's gateway refusal was not bypassed; final matrix captures use the real desktop HTTP adapter with its existing loopback checks.

## F08 — Companion deep-link hydration (P1 / Fixed in E5C, `e3b398f`)

Directly opening `?companion=1&tab=chat`, `agents`, `missions` or `settings` emits **minified React error #418** in every tested Silver and Graphite case. Home does not emit that error. These are eight FAIL records in `baseline.json`, not clean-console screenshots. The content subsequently renders, which is why a screenshot alone would miss the problem.

The likely cause is visible at `phone.tsx`'s route initializer: the server parses an empty search string while the client's first render parses `window.location.search`, choosing different first-paint content for non-Home tabs. E5C should derive both renders from the same router search. E5D must verify direct links, reload, Back, tab focus and clean hydration in the built output. Do not suppress React errors or count client recovery as a pass. [Graphite Chat](evidence/companion-chat-graphite-mobile-web.png), [Silver Settings](evidence/companion-settings-silver-mobile-web.png).

**Fixed in E5C (`e3b398f`):** both renders derive from the same router search; verified in E5D — clean hydration on all four deep-linked tabs, reload and reload-Back (see [E5D qualification](../e5d/QUALIFICATION.md)).
