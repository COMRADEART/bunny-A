**First hosted run of `7ccced6` failed two jobs.** Both causes were in the new installer test harness, not in the
installer:
- `full MA3/MA4 regression` (run 40715800014): only test 1-2 failed. The CI temp folder is an 8.3 short path
  (`RUNNER~1`), which the installer records expanded (`runneradmin`), and the test compared the raw strings.
- `Build WPF preview` (run 40715799924): 5 of 6 failed with "Get-FileHash … is not recognized". The workflow step runs
  under `pwsh`, and the spawned Windows PowerShell inherited PowerShell 7's `PSModulePath`.

The test now compares resolved paths and starts Windows PowerShell without `PSModulePath`. Locally, 6/6 pass both
normally and with a PowerShell 7 style `PSModulePath` set. No assertion was weakened.

`native/voice/bunny-voice-worker.json` was regenerated by `npm test` and restored again. The hosted CI runs for the
final S1R1 head are recorded in the PR #59 description and the final report (same rule as below).
